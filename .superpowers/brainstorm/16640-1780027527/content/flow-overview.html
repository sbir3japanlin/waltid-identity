Three Credential Flows — API Map

Each flow follows the same pattern: Issuer creates offer → Wallet claims → Verifier requests → Wallet presents → Verifier checks

Common Flow Pattern

All three flows share this structure

0. POST /auth/register
1. POST /auth/login
2. GET /wallet/accounts/wallets
3. GET /wallet/{id}/keys
4. GET /wallet/{id}/dids
8/10. POST /exchange/useOfferRequest

Three Credential Formats

mDoc (ISO 18013-5)

mobile Driver's License format. Uses IACA → DS certificate chain, mdoc-specific namespaces and paths, ISO 18013-7 OID4VP profile.

Issues via /openid4vc/mdoc/issue
Verifies with ISO_18013_7_MDOC profile

SD-JWT VC

IETF Selective Disclosure JWT. Fields can be individually disclosable (sd: true/false). Uses vc+sd-jwt format with Presentation Exchange.

Issues via /openid4vc/sdjwt/issue
vp_policies: ["signature_sd-jwt-vc"]

JWT VC/VP (W3C)

Standard W3C Verifiable Credentials in JWT format. Uses credential types like UniversityDegree with Presentation Exchange.

Issues via /openid4vc/jwt/issue
standardVersion: DRAFT13
