Architecture Approaches

Three React (Vite) SPAs, each supporting mDoc + SD-JWT + JWT VC/VP

A

Monorepo with shared API layer

Three Vite apps in a monorepo (e.g., apps/wallet/, apps/issuer/, apps/verifier/) plus a shared packages/api-client/ that contains typed HTTP functions for all three backend services.

Pros

  • API logic written once, shared across all three apps
  • TypeScript types shared across apps
  • Single npm install / npm run dev with Turborepo
  • Easy to add new credential formats later

Cons

  • Slightly more setup complexity
  • Monorepo tooling overhead (workspaces, turbo)
B

Three standalone apps, shared patterns

Each app is a completely independent Vite project. API call functions are duplicated in each app but follow the same naming/pattern conventions. Each app runs on its own port.

Pros

  • Simplest individual setup — standard Vite app
  • No monorepo tooling needed
  • Each app can evolve independently

Cons

  • Code duplication across apps
  • Inconsistent after changes in one app
  • Harder to refactor shared patterns
